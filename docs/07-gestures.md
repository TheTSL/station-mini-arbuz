# 07. Датчик жестов (VL53L0)

## Устройство

```
/dev/input/event0   STM VL53L0 proximity sensor
i2c 1-0029          stmvl53l0
sysfs: /sys/class/input/event0/device/
  enable_ps_sensor     1 — включить датчик (по умолчанию 0!)
  enable_debug
  set_delay_ms
  set_range_profile
  set_timing_budget
```

## Ключевая находка

Без `maind` датчик **выключен** (`enable_ps_sensor = 0`) и событий не выдаёт.
Включение:

```sh
echo 1 > /sys/class/input/event0/device/enable_ps_sensor
```

После этого evdev-поток идёт (в среднем ~100 событий/сек).

## Формат событий

EV_ABS с кодами:

| Код | Значение |
|---|---|
| 8 | `ABS_WHEEL` — **расстояние в мкм** (450000 = 450 мм) |
| 17 | производная величина (растёт с расстоянием) |
| 20, 21 | вспомогательные |

Фон в комнате: 430–550 мм, шум ±100 мм. Рука: 80–320 мм.

## Управление громкостью удержанием в зоне

Текущий `scripts/volgest.c` читает `/dev/input/event0` только в режиме `maind-free`.
Событие `ABS_WHEEL` переводится из микрометров в миллиметры и сглаживается EMA.

- Удержание в зоне 130–300 мм не менее 150 мс включает управление громкостью.
- Ближе — тише, дальше — громче; диапазон делится на 40 уровней.
- Выход за 350 мм завершает жест с гистерезисом.
- Значение применяется через штатный `/system/workdir/bin/amixer`, без линковки с
  проблемной статической ALSA-библиотекой.
- Удержание на расстоянии до 90 мм в течение 700 мс переключает `SPK mute`.
- Сглаженное расстояние сохраняется в `/tmp/volgest.dist` для диагностики.

Проверено на подключённой колонке 2026-10-26: `amixer` изменял Master от 0 до 100%,
демон печатал применённые уровни. Датчик имеет нижний предел около 88 мм, поэтому
порог 90 мм означает почти вплотную к корпусу. Демон запускается только вне `maind`.

Кольцо индикации в этом скрипте использует экспериментальные I²C-записи. Они не дают
стабильного управления LED на этой плате; основное управление громкостью от них не зависит.

## Что не получилось

Направление жеста (вверх/вниз) надёжно не определяется: одно движение руки даёт и подход (расстояние падает), и уход (растёт), из-за чего эвристика срабатывает дважды в противоположных направлениях. Поэтому текущий вариант меняет громкость по удерживаемому расстоянию, а не по направлению движения.

Попробованные подходы:

1. мгновенная дельта — слишком шумно;
2. тренд за 250–400 мс — срабатывает многократно;
3. якорь с перецентровкой — сбрасывается на медленном движении;
4. гистерезис (повтор только после возврата в фон) — ложные срабатывания на шуме;
5. сглаживание EMA + окно 600 мс — жест не распознан;
6. решение по последнему участку после разворота — не сработало.

Вывод: нужен либо разбор алгоритма `gestured` из `maind`, либо другой, детерминированный способ управления (например, удержание руки в двух разных зонах).

## Наблюдение про maind

Когда `maind` активен и обрабатывает жест, он **захватывает** event0 (сторонние читатели событий не получают). Когда простаивает — события доступны. Это мешает снимать эталонные трассы одновременно с работой штатного распознавания.
