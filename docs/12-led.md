# 12. LED-кольцо

## Что известно

- В device tree узел `aml,ledring` (i2c-1, 0x1f, `aml_pca9557`), но **драйвер не привязан**; в ядре `CONFIG_AMLOGIC_LEDRING is not set`.
- На `i2c-0` по адресу `0x3c` висит `ti,sn3236` (36-канальный LED-драйвер).
- `/sys/class/leds/` пуст, отдельного `/dev`-узла нет.
- Кольцом управляет **`mv_ioguard`**: в бинаре есть `i2c_dev`, `led_function`,
  `led_effect_start`, `led_polling_thread`, `g_led_controller`, а также уведомления
  `GNOTIFY=MCULEDANGLE/MCULEDIDLE/MCULEDLISTENING/MCULEDTHINKING/MCULEDPLAYTTS`.

## Рабочий протокол чипа (проверено)

Порядок записи **важен**. Работает такая последовательность (пакетная запись в `0x3c`):

1. записать 36 байт PWM в регистры `0x00..0x23` (одной посылкой);
2. `0x24` — глобальный ток (0…255);
3. `0x25 = 0x01` — normal operation;
4. `0x26 = 0x00`;
5. `0x27 = 0x00` — latch/update.

Проверено: при таком порядке кольцо загорается (все каналы 255, ток 127 — голубой цвет
с одним красным светодиодом). Если писать `0x24/0x25` до PWM — эффекта нет.
Одиночные записи регистров (по 2 байта) не срабатывают, нужна пакетная посылка.

## Почему не держится

Состояние сбрасывается примерно через секунду: `mv_ioguard` переписывает чип.
Остановить его не удаётся — его сразу перезапускает супервизор (PID меняется).
Перезапись кадра каждые 100 мс тоже не помогает — `mv_ioguard` всё равно сбрасывает.

## Следующие шаги

1. Найти супервизор, который поднимает `mv_ioguard` (init-скрипт/лаунчер), и на время
   эксперимента не давать ему перезапускаться.
2. Либо разобрать формат команд `mv_ioguard` (сокеты `/tmp/RequestIOGuard`,
   `/tmp/RequestGoheadCmd`, `/tmp/volumeprompt`): строки `GNOTIFY=...` он принимает,
   но нужный формат/команда для подсветки пока не подобраны.
3. После этого можно сделать индикацию: цвет статуса, «полоску» громкости, реакцию на
   события бота.

## Осторожно

Все 36 каналов на максимуме при токе `0x7F` совпали с перезагрузками колонки
(просадка питания). Работать на малой/средней яркости.
