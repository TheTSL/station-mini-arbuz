# 12. LED-кольцо

## Что известно

- В device tree узел `aml,ledring` (i2c-1, 0x1f, `aml_pca9557`), но **драйвер не привязан**; в ядре `CONFIG_AMLOGIC_LEDRING is not set`.
- На `i2c-0` по адресу `0x3c` висит `ti,sn3236` (36-канальный LED-драйвер, только запись).
- `/sys/class/leds/` пуст.
- **Кольцом управляет `maind`**: у процесса есть `fd -> /dev/i2c-0`, и он линкует
  `libwmlighteffect.so` (в нём же `led_function`/`led_effect`-подобные символы).
- `mv_ioguard` (потомок `rootApp`, стартует из `S05linkplay.sh`) держит **`/dev/ttyS3`**
  — это линия к MCU; в нём же уведомления `GNOTIFY=MCULED...` и UART-команды
  `AXX+ANG+%.3d`, `AXX+SET+RTC...` и т.п.

## Что проверено

1. Прямая запись в `sn3236` **пакетом** в правильном порядке
   (36 байт PWM → 0x24 ток → 0x25=1 → 0x26=0 → 0x27=0) даёт **кратковременную
   вспышку** кольца (голубой + один красный светодиод).
2. Порядок критичен: если писать 0x24/0x25 до PWM — эффекта нет. Одиночные записи
   регистров не работают.
3. Чтение регистров не поддерживается (`i2cget` → Read failed).
4. Записи в `ttyS3` от `mv_ioguard` во время wake-word не наблюдаются — значит
   подсветку он не шлёт.
5. Остановка `rootApp`/`mv_ioguard` не помогает удержать свет.
6. Попытка перехватить I²C через **LD_PRELOAD** (`libi2clog.c`, версия с `dlsym`)
   **уронила `maind`** — конфиг откатили. Версия через `syscall(SYS_ioctl)` +
   перехват `write()` собрана, но проверить её на статических утилитах нельзя
   (LD_PRELOAD не работает со static binaries); нужен динамический тест.

## Следующий шаг

1. Собрать **динамический** aarch64/armhf тест (не `-static`), проверить, что шим
   логирует `write()` в i2c-fd.
2. Поднять `maind` с `LD_PRELOAD=/data/opt/libi2clog.so`, сказать «Алиса» — снять
   точные кадры, которые `libwmlighteffect` пишет в `0x3c`.
3. Повторить их в своём режиме (когда `maind` выключен) — там кольцо никто не сбросит.

## Наблюдение про перезагрузкиПри зависании `maind` колонка иногда уходит в ребут — в системе есть `watchdogd`
(PID 500). Тяжёлые эксперименты (`strace -f`, битый `LD_PRELOAD`) приводили к
зависанию и последующей перезагрузке. Вывод: инструментацию делать аккуратно,
не вешать `strace -f` на `maind` надолго.

## Трассировка maind (последнее)

- У maind --platformd есть d 29 -> /dev/i2c-0.
- Во время wake-word он делает **ioctl(fd 29, I2C_RDWR (0x0707), ...)** — 546 вызовов за несколько секунд.
- LD_PRELOAD-шим, перехватывающий ioctl()/write(), **не поймал** эти вызовы, хотя библиотека загружена
  (/proc/<pid>/maps), — вероятно, maind вызывает syscall() напрямую, минуя libc-обёртку.
- Следующий шаг: перехватывать syscall() (raw svc 0 для ARM) или снимать I²C на уровне ядра/логическим
  анализатором, затем воспроизвести кадры.
