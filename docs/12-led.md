# 12. LED-кольцо

## Что известно

- В device tree узел `aml,ledring` (i2c-1, 0x1f, `aml_pca9557`), но **драйвер не привязан**; в ядре `CONFIG_AMLOGIC_LEDRING is not set`.
- На `i2c-0` по адресу `0x3c` висит `ti,sn3236`.
- `/sys/class/leds/` пуст, отдельного `/dev`-узла нет.
- Кольцом управляет **`mv_ioguard`** (потомок `rootApp`, запускается из `S05linkplay.sh`):
  в бинаре есть `i2c_dev`, `led_function`, `led_effect_start`, `led_polling_thread`,
  `g_led_controller`, уведомления `GNOTIFY=MCULED...`, а также UART-команды MCU:
  `AXX+ANG+%.3d`, `AXX+SET+RTC...`, `AXX+SET+WEK...` и т.п.

## Что проверено

1. Прямая запись в `sn3236` (`/dev/i2c-0`, 0x3c) **пакетом** в правильном порядке
   (36 байт PWM → 0x24 ток → 0x25=1 → 0x26=0 → 0x27=0) даёт **кратковременную
   вспышку** кольца (голубой, один красный светодиод).
2. Порядок критичен: если писать 0x24/0x25 до PWM — эффекта нет. Одиночные записи
   регистров не работают, нужна пакетная посылка.
3. Чтение регистров не поддерживается (`i2cget` → Read failed), чип только на запись.
4. Остановка `rootApp`/`mv_ioguard` (они не перезапускаются до ребута) **не помогает**:
   кольцо всё равно не держит свет. Значит `sn3236` — не основной путь управления
   кольцом; вероятно, кольцом рулит **MCU по UART**, а `mv_ioguard`/`rootApp` шлют ему
   команды `AXX+...`.

## Следующий шаг

Разбирать UART-протокол между `rootApp`/`mv_ioguard` и MCU (какой порт, скорость,
формат кадров `AXX+...`), либо найти в сокетах `mv_ioguard` команду, которая меняет
подсветку. После этого — индикация: цвет статуса, полоска громкости, события бота.

## Осторожно

Все 36 каналов на максимуме при токе `0x7F` совпали с перезагрузками колонки
(просадка питания). Работать на малой/средней яркости.
