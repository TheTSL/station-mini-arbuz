# 01. Прошивка и обновления

## Устройство

- Модель: Yandex Station Mini 1, `YNDX-0004`
- Платформа: `yandexmini`
- SoC: Amlogic A113X (4 ядра Cortex-A53)
- ОС: Buildroot, ядро Linux 4.9.68 (сборка 2025-07-21)
- Корневая ФС: UBIFS, смонтирована rw (`/dev/ubi0_0`), отдельный `/bkupgrade` (`/dev/ubi1_0`)

## Версии

| Версия | Дата | Комментарий |
|---|---|---|
| `1.3.4.12.532420178.20191021` | 2019 | заводская, не поддерживает удалённую активацию ADB |
| `1.305.4.16.3237824040.20250721` | 2025-07-21 | **рабочая**: принимает сертификаты, `remoteActivation` работает |
| `1.369.4.24` / `1.369.4.50` | 2026 | активация ADB через конфиг не работает / сертификаты отозваны |

## Как устроен даунгрейд

1. Поднимается локальный HTTPS-прокси с цепочкой eMudhra для `quasar.yandex.net`.
2. DNS колонки уводит `quasar.yandex.net` на прокси.
3. На `/check_updates` прокси отдаёт манифест на нужную (более старую) версию; колонка скачивает образ по HTTP.
4. Установщик применяет образ и перезагружается.

Ключевой момент: условие «версия отличается», а не «версия новее» — иначе даунгрейд не предлагается.

## Маркеры и проверка версии

- Версия: `/system/vendor/quasar/VERSION`, `version_full`
- Маркеры активации ADB: `/data/quasar_activate_adb_quasmodrom`, `/data/quasar_activate_network_adb`
- Лог активации: `/data/quasar/quasar_adb.log`
- Признак неудачного обновления: `/data/quasar/data/update-info.json` с `toVersion` новее текущей

## Блокировка OTA

- `device_ota_update.sh` заменён заглушкой `exit 0` (оригинал — рядом, `.real`).
- `updatesd` убран из `servicesList` в `quasar.cfg` и из `launch.json`.
- Запись `update-info.json` удаляется, чтобы колонка не считала обновление начатым.
